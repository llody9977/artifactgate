THE PROBLEM

Using a vendor image transfers risk into your environment

A mutable tag can point to different bytes tomorrow. The image can contain vulnerable, malicious or poorly maintained components. Its upstream build history may be absent. A clean scan can become stale, and the application sidecar may carry a separate risk from the main image.

ArtifactGate does not assume that these uncertainties disappear. It makes them visible, applies policy to the evidence available now, and records the boundary of the decision.

THE DECISION MODEL

Six questions, one exact artifact pair

01

Source

Did it come from an allowed upstream and an accepted version?

02

Which immutable OCI digests were actually assessed?

03

Composition

What does the digest-bound SPDX SBOM declare is inside?

04

Risk

What do CVE, KEV, EPSS, age, malware, secret, OpenVEX and bounded runtime signals show?

05

Decision

Did policy allow promotion, or did we sign expiring OpenVEX exception statements?

06

Continuity

Can deployment verify and monitor the same application and runner bytes?

CONTROLLED PROMOTION

Quarantine → assess → decide → attest → deploy → re-check

The upstream image is never treated as internally trusted merely because it can be pulled. ArtifactGate resolves the digest first, evaluates the application and runner together, fails closed when required evidence is unknown, and promotes the accepted pair into a controlled namespace. Deployment verifies GitHub OIDC-backed attestations and pins both digests.

WHAT TO LOOK OUT FOR

Questions to ask before trusting any third-party image

Registry Takeover Risk

Is the upstream registry account secure? Threat actors compromise maintainer accounts to distribute malicious updates.
Boundary: Warning-Only. The gate detects signature presence, but cannot verify the original publisher account's security. We mitigate this by requiring cryptographic signing where available.
Incident: The ua-parser-js library hijack (2021), where compromised developer credentials were used to publish packages containing cryptomining malware (CVE-2021-42048).

Silent Tag Drift Risk

Are we pulling mutable references? Relying on tags like latest allows upstream code to change without your knowledge.
Boundary: Enforced Prevention. The ingestion gate requires resolving version tags to immutable digests first. Pinned digests cannot drift.
Incident: The Docker Hub spoofing campaign (2023), where threat actors pushed millions of drifted, malicious images spoofing legitimate software to execute cryptominers (Sysdig Threat Report).

Socially Engineered Logic Bombs

Is the codebase immune to malicious contributors? A contributor can spend years introducing obfuscated backdoors that static scans miss.
Boundary: Structural Limitation. Static scans cannot detect intentional logical backdoors. The gate runs kernel-level eBPF tracing during smoke tests to monitor runtime executions, but this covers only active test paths.
Incident: The XZ Utils backdoor (2024), where a trusted maintainer spent years planting a sophisticated build-time SSH authentication bypass (CVE-2024-3094).

Pipeline Takeover & Token Theft

Can the container compromise the build pipeline? A malicious dependency can execute install scripts to harvest secrets from ambient environment variables.
Boundary: Partial Prevention. We run workflows with read-only GitHub OIDC tokens and isolate dependencies, but any build-time execution risks exfiltrating ambient variables if exposed.
Incident: The Codecov Bash Uploader compromise (2021), where a compromised script silently exfiltrated CI environment credentials (CISA Alert AA21-117A).

Container Escape & Privileges

What is the worst-case blast radius? Running as root or with high capabilities enables container breakouts to the host.
Boundary: Enforced by IaC Policy. The gate scans deployment manifests for insecure capabilities or root execution and blocks them.
Incident: The runc container escape (2024), where a runtime file descriptor leak allowed attackers to break container boundaries and gain host root access (CVE-2024-21626).

Post-Promotion Security Decay

How do we handle new disclosures? An image that was clean at promotion decays as new vulnerabilities are discovered.
Boundary: Partial (Active Detection). The gate scans the deployed digest weekly, but cannot prevent zero-days exploited before public disclosure.
Incident: The Cleo File Transfer campaign (December 2024), where zero-day vulnerabilities were actively weaponized before patches or CVE records were published (CVE-2024-50623).

Sidecar & Runner Exposure

Are we verifying the entire bundle? Hardening the main application while leaving task runners or sidecars unverified leaves a backdoor.
Boundary: Enforced. The policy configures that all companion runner images must be resolved to digests and evaluated under the same promotion rules.
Incident: Companion containers (such as unpinned local databases or runners) serving as entry points to otherwise secure workloads.

Waiver & Exception Decay

Are exceptions auditable and expiring? Permanent exceptions become permanent backdoors.
Boundary: Enforced. The workflow requires exceptions to target specific CVEs, document compensating controls, and declare an expiry date.
Incident: Stale, unmonitored security exceptions leading to compromise of legacy enterprise services.

VERIFY, DO NOT ASSUME

Bind the decision to the bytes deployed

gh attestation verify oci://IMAGE@sha256:DIGEST -o llody9977

Verify both the n8n application and external runner subjects, then deploy both by immutable digest. The promotion attestation proves that ArtifactGate's workflow handled those digests; it does not recreate missing provenance for the vendor's original build.

ASSURANCE BOUNDARY

Promotion is a risk decision, not a security certificate

A successful result means the exact pair passed the documented policy or a scoped, justified and expiring exception was approved. It does not mean vulnerability-free, compliant or suitable for every environment. SBOMs and scanner feeds may be incomplete or delayed. Runtime observations cover only exercised smoke-test paths, and “not observed” is not proof that vulnerable code is unreachable.

OUT OF SCOPE

What ArtifactGate structurally cannot do

Detect Obfuscated Backdoors

It cannot find custom, obfuscated logic bombs in source dependencies through static scans. Runtime eBPF monitoring flags anomalous actions, but only on paths exercised by tests.

Verify Vendor Build Integrity

Absent upstream cryptographic provenance, the gate only proves that the image matches a resolved digest. It cannot prove that the vendor's build pipeline was secure or untampered.

Assess Application Logic

The gate runs dynamic smoketests and generic vulnerability scans. It cannot perform custom application-layer penetration testing or verify the logical correctness of n8n workflows.

Guarantee Day-Zero Immunity

A promoted image is only clean against known datasets at the time of scanning. A zero-day exploit or delayed CVE registration will bypass the promotion gate.
